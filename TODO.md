# VitaminOS26 — план работ по железу

Статусы: `[ ]` не начато, `[~]` в работе, `[x]` сделано, `(q)` проверено в QEMU.

## 1. Диски: HDD и простой SATA-SSD
- [x] ATA PIO (IDE/HDD, primary master/slave).
- [x] AHCI/SATA (SSD, DMA, опрос без прерываний).
- [x] Выбор целевого диска + установка на выбранный диск.
- [x] Убрать NVMe (это ОС для старого железа).
- [x] Мелочи: модель/серийник в `disks`, сброс порта при ошибке.

## 2. Ввод: USB-клавиатура
- [x] PCI: найти UHCI (класс 0x0C/03/00) и EHCI (0x0C/03/20).
- [x] UHCI: сброс, frame list, включение портов.
- [x] Перечисление: control transfers (device/config descriptors).
- [x] HID boot protocol: SET_PROTOCOL(0) + interrupt-IN опрос.
- [x] Отдавать события в `keyboard.rs` (единый поток с PS/2).
- [x] Оставить рабочим BIOS USB legacy (8042) как fallback.
- [x] Две разметки link pointer (спецификация UHCI и модель QEMU), выбор по
  результату первого обмена — иначе не работает ни то, ни другое.
- [ ] Позже: OHCI/EHCI (USB 2.0), SET_IDLE для отчётов по таймеру.

## 3. Дисплей: разрешение под монитор
- [x] Разбор multiboot2-тега 8 (framebuffer) в ядре.
- [x] Встроенный шрифт 8x16 (`src/font8x16.bin`).
- [x] `fb.rs`: блит текстового буфера в линейный фреймбуфер с масштабом.
- [x] Тень текста в RAM: VA 0xB8000 в ring3 и ядре смотрит в тень.
- [x] GRUB: режим по EDID через header-тег 5 (проверено 640x480..1920x1080).
- [x] Свой stage2: VBE (INT 10h 4F00/4F01/4F02) + тег 8 в mb2-инфо.
      Сборка тега проверена сквозным прогоном; на SeaBIOS его собственная
      реализация VBE отдаёт один негодный режим, поэтому там остаётся
      текстовый режим (на живой BIOS с полным VBE будет нативное разрешение).
- [x] Fallback: нет тега 8 -> VGA text как сейчас.
- [x] Скорость отрисовки: кадровый буфер отображается с кэшированием
      (`paging::map_phys_cached`; через `NO_CACHE` каждая запись пикселя шла
      мимо кэша CPU), строка текста растеризуется целиком в буфер и копируется
      в кадр крупными кусками вместо тысяч мелких записей, палитра и цвета
      ячеек считаются один раз на строку.
- [x] `LAST` обновляется из того же снимка текста, что попал в кадр: при
      прежней схеме символы, дописанные между сканированием и отрисовкой,
      помечались «уже нарисованными» и пропадали с экрана.
- [x] Композитор рисует сразу и ждёт один тик (было - два тика и сон до
      отрисовки, из-за чего большой вывод ложился на экран ступеньками).
- [ ] Оптимизация сборки ядра (`opt-level >= 1`) сломана: задача композитора
      уходит в мусорный адрес, система зависает через несколько секунд после
      загрузки (не работают ни ввод, ни вывод). Проверено минимальным
      сценарием - достаточно любой записи из задачи композитора, даже в
      обычную память. При `opt-level = 0` система работает устойчиво, поэтому
      профиль оставлен прежним; причина в планировщике или разметке MMIO,
      нужно разбираться отдельно (задача зависает вся целиком: IF=0, RIP
      уходит за пределы образа ядра).

## 4. Учётные записи и права доступа
- [x] SHA-256 (своя реализация, проверена на векторах NIST) + соль в `/etc/shadow`.
- [x] Учётные записи в `/etc/passwd`, поиск по имени и uid, следующий свободный uid.
- [x] uid в иноде (свободные байты 84..86) + девять бит rwx: формат ФС не изменился.
- [x] Проверки прав в VFS: проход по пути (`x`), чтение (`r`), запись (`w`),
      создание/удаление в каталоге (`w`+`x`); отказ отличается от `no such file`.
- [x] Вход при загрузке: пароль без эха, три попытки, после исчерпания система
      останавливается; root за консолью не пускается; на образе без учётных
      записей вход не спрашивается.
- [x] Домашний каталог пользователя с ним самим владельцем, `/tmp` — общий.
- [x] Учётные данные в задаче (`Task::uid`): права программы не текут в шелл.
- [x] `sudo` (пароль проверяет ядро) для встроенных команд шелла и программ из
      `/bin`; `chown`/`chmod`, `whoami`, `id` в шелле.
- [x] `adduser` / `removeuser` через `sudo` (системные вызовы useradd/userdel).
- [x] `tools/mkfs.py --user имя:пароль` — образ с готовыми учётными записями.
- [ ] Позже: группы (gid), `sudoers` с правилами без пароля, KDF с повторениями
      (PBKDF2) вместо одного раунда SHA-256, запрет входа root с загрузочной флешки.
