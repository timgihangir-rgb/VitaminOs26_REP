# VITAFS - on-disk формат файловой системы VitaminOS26 (Фаза 3)

Заменяет легаси-слепок (`VOS26IMG`, см. `src/disk.rs`) на настоящую блочную ФС
с inode-таблицей и журналированием. Диск: сырой образ 8 МиБ, ATA primary master.
Логический блок = 4096 байт = 8 секторов по 512 (`blockdev::BLOCK_SIZE`).

## Раскладка диска

    Блок      Назначение
    0         суперблок
    1..=64    журнал WAL (64 блока = 256 КиБ)
    65..=66   битмап занятых блоков данных
    67..=68   битмап свободных inode (на 1024 inode хватает 1 блока, запас)
    69..=100  таблица inode (32 блока = 1024 inode по 128 Б)
    101..     данные (блоки файлов, косвенные блоки)

Все числа little-endian.

## Суперблок (блок 0)

    Смещение Размер Поле
    0        8      magic "VITAFS1\0"
    8        u32    version = 1
    12       u32    block_size = 4096
    16       u32    total_blocks (из размера образа)
    20       u32    total_inodes
    24       u32    free_inodes (информационно, истина в битмапе)
    28       u32    journal_start_block = 1
    32       u32    journal_blocks = 64
    36       u32    inode_table_start = 69
    40       u32    data_start = 101
    44       u32    flags: bit0 = dirty (не было чистого размонтирования)
    48       u32    root_inode = 2 (см. ниже)

## Inode

Таблица начинается с inode № 1; номер хранится как u32, 0 = "нет".
Резервные номера: 1 = журнал/служебный (не используется), 2 = `/` (корень).

    Размер записи: 128 байт => по 32 inode на блок => total_inodes = 1024.

    Смещение Размер Поле
    0        u16    тип: 0 free, 1 file, 2 dir, 3 symlink, 4 chardev, 5 blkdev
    2        u16    права (rwxrwxrwx, сейчас не enforced, однопользовательская ОС)
    4        u32    размер в байтах
    8        u32    число жёстких ссылок (всегда 1; каталогам - 2 условно)
    12       u32    atime (unix, сек)
    16       u32    mtime (unix, сек)
    20       u32    device_id для chardev/blkdev (номер драйвера)
    24..84   union (как в ext2):
               - 12xu32 direct[0..12]      (24..72)
               - u32  indirect1            (72..76) - блок u32 x 1024
               - u32  indirect2            (76..80) - резерв, должен быть 0
               - u32  indirect3            (80..84) - резерв, должен быть 0
               - либо 60Б цель fast-symlink, если тип = symlink и размер <= 60
                 (тогда указатели считаются нулями и не валидируются)
    84..128         запас (нули)

Максимальный размер файла: 12 + 1024 = 1036 блоков ≈ 4.14 МиБ.
Для программ (/bin/*, макс ~24 КиБ) хватает прямых блоков.

## Каталог

Обычный файл типа dir; содержимое - массив записей:

    Смещение Размер Поле
    0        u32    inode ребёнка (0 = дырка/удалённая запись)
    4        u8     длина имени (1..=58)
    5        59     имя (UTF-8 без NUL)

Запись фиксирована 64 байтами; каталог растёт блоками по 4096 (64 записи).

## Журнал (WAL)

Кольцевой лог транзакций. Каждая транзакция:

    [data block | tag=JDATA]... [commit block | tag=JCOMMIT, seq=u64, nblocks]

Порядок записи: сначала тела (данные+метаданные как полные образы блоков),
последним - commit-блок с инкрементальным seq. Атомарность обеспечивает то,
что commit-блок появляется на диске последним.

При монтировании:
  1. если суперблок.dirty или найден commit с seq > last_replayed_seq -
     реплей: копируем тела всех завершённых транзакций на место;
  2. незавершённые (без commit) - игнорируются;
  3. fsck-lite: сверяем битмапы с фактическим использованием inode;
  4. лог очищается (запись пустого заголовка).

В памяти транзакции буферизуются списком изменённых блоков; `commit()` пишет
тела в кольцо, затем commit-блок; после успешной записи тел на свои места
(через bcache + flush_all) транзакция считается применённой.

## Устройства (/dev)

chardev-inode с device_id из таблицы:

    0 null (read: EOF, write: /dev/null)
    1 zero (read: нули)
    2 tty  (консоль VGA+клавиатура, ioctl)
    3 keyboard (read: очередь сканкодов/символов)
    4 vga  (прямой доступ к текстовому буферу через read/write)

ioctl(int80, fn=IOCTL, fd/dev, cmd, arg): get/set cursor, echo on/off,
clear, screen size. Номера команд - в progabi.

## Пути

Единый резолвер: нормализация `.`, `..`, повторных слэшей; лимит симлинков 8;
таблица монтирования `(источник -> точка_монтирования)`; chroot меняет корень
процесса шелла (односторонне).
