# VitaminOS26 — что реализовано

Хобби-ОС на Rust (ядро) + x86_64 assembly (загрузка). Версия **v0.1.0**.

## Загрузка и старт
- Multiboot2 + GRUB, загрузка ELF по адресу 2 МБ.
- Загрузочный экран с ASCII-логотипом и статусами подсистем держится до
  нажатия Enter, после чего система спрашивает логин и пароль.
- Собственный 32→64-битный трамплин в `src/boot.asm`: PML4/PDP/PD, PAE, long mode, GDT, стек 16 КБ, identity-маппинг первых 4 МБ.
- Баннер «VitaminOS26 - Welcome!», инициализация: VGA, COM1, память, файловая система, планировщик, PIT 100 Гц, init-система, шелл.

## Память
- Куча 1 МиБ (`linked_list_allocator`), офсет 4 ГБ, `OffsetPageTable`, frame-аллокатор из Multiboot2 memory map.
- Резерв низкой памяти под ABI: `0x5000` SysInfo, `0x6000..` буфер vita/help, `0x708C/0x7090` позиция выхода, `0x7800..` ABI-указатели.

## CPU / прерывания
- Один CPU, два PIC 8259 (IRQ0 = PIT 100 Гц, остальные замаскированы).
- GDT + TSS (IST для double fault), IDT, общий обработчик исключений, PIT 11932.
- CPUID: vendor, brand, family/model/stepping, флаги SSE/SSE2/AVX/RDRAND, cores/threads.

## Планировщик и задачи
- Вытесняющий round-robin 100 Гц, до 16 задач (0 = шелл), стек 16 КБ на задачу.
- `spawn / kill / list / ps`, состояния Ready/Running/Finished, переключение контекста на таймере.
- Фоновые демоны `bg`: `prime`, `fib`, `parallel` (воркеры с барьером через атомики), `ticker`, `crashy` (демо рестарта).

## Ввод / вывод
- PS/2-клавиатура опросом (scancode set 1): Shift, Backspace, стрелки, история команд.
- Текстовый экран 80×30 рисуется композитором в линейный кадровый буфер: строка
  текста растеризуется целиком в промежуточный буфер (палитра и цвета ячеек
  считаются один раз на строку) и переносится в кадр одной крупной записью на
  строку глифа; кадровый буфер отображен с кэшированием, иначе каждая запись
  пикселя шла бы мимо кэша CPU.
- VGA-текст 80×30, BIOS-шрифт 8×16 (plane 2), курсор, скроллинг, цвета.
- Serial COM1 (лог для QEMU).

## Шелл (VitaminShell 0.1.0)
- Промпт `[стол] vitamin_os26:<пользователь>@<pwd>$`.
- Команды: `clear`, `version`, `ls`, `pwd`, `cd`, `mkdir`, `rmdir`, `touch`, `rm`, `cat`, `cp`, `mv`, `find`, `echo` (в т.ч. `> file`, `>> file`, `< file`), `sudo`, `whoami`, `id`, `chown`, `chmod`, `run`, `bg`, `ps`, `kill`, `init`.
- Неизвестная команда → попытка запуска `/bin/<имя>` в foreground.

## Учётные записи и права доступа
- Учётные записи в `/etc/passwd` (`имя:uid:домашний_каталог`), пароли — SHA-256
  от соли и пароля в `/etc/shadow` (`имя:соль:хеш`); SHA-256 своя, без crates.io.
- Вход при загрузке: имя и пароль, пароль не отображается, три попытки; после
  исчерпания система останавливается и шелл не запускается. root за консолью не
  пускается. Если на ФС нет ни одной учётной записи (live-образ) — вход не
  спрашивается.
- Права в иноде: владелец (uid) + девять бит rwx (владелец/остальные). uid лежит
  в свободных байтах инода, формат ФС не меняется, старые образы читаются как
  принадлежащие root.
- Проверки в VFS: `x` на каталоге при проходе по пути, `r` на чтение, `w` на
  запись, `w`+`x` на родительском каталоге для создания и удаления. Отказ по
  правам отличается от прочих ошибок: `permission denied` вместо `no such file`.
- `/tmp` доступен всем на запись, домашний каталог принадлежит своему
  пользователю, всё остальное (`/etc`, `/bin`, `/boot`, `/var`) — root'у.
- Учётные данные хранятся в задаче (`Task::uid`), поэтому права программы не
  распространяются на шелл и на фоновые службы.
- `sudo <команда>`: пароль спрашивает и проверяет ядро (`auth`), команда идёт от
  root, права возвращаются после неё. Отдельного `setuid` нет намеренно — иначе
  любая программа повысила бы себя сама.
- `sudo adduser <имя>` и `sudo removeuser <имя>` — создание и удаление записей
  вместе с домашним каталогом.

## Файловая система и диск
- In-memory VFS (дерево, арена узлов): `/bin`, `/etc`, `/home`, `/tmp`, `/var`, `/var/log`.
- ATA PIO (primary master), сериализованный слепок VFS на диске (magic `VOS26IMG`, суперблок сектор 0), персистентность между перезагрузками.
- Флаш на диск после каждой команды; загрузка слепка при старте.

## Пользовательские программы (`/bin`, внедрены в ядро)
- **clock** — CMOS RTC, 12/24 ч, конфиг `/etc/timezone`, демон-режим в `/tmp/clock.log`.
- **example** — «Hello from C!».
- **fetch** — ASCII-лого «V в круге» + системная информация (OS, kernel, CPU, память, флаги), продолжение tty при нехватке места.
- **help** — справка по командам и программам.
- **snake** — змейка 60×20 (WASD, Q), счёт на экране, тайминг по PIT.
- **vita** — текстовый редактор: до 500 строк/4 КБ, навигация, Ctrl+S, Ctrl+Q, аппаратный курсор.
- **sudo** — запрос пароля и запуск команды от root.
- **adduser** / **removeuser** — создание и удаление учётных записей (нужны права root).

## Исполнение программ
- Статические ELF64 (C / Rust no_std) с диска, ring 3, своё адресное пространство на задачу.
- ABI через трамплины в низкой памяти (`0x7800..`): `ticks / hlt / sleep /
  vfs_read / vfs_write / kbhit / kbread / ioctl / net_* / auth / getuid /
  whoami / useradd / userdel / exec / wait`.
- `exec(path, argc, argv)` и `wait(pid)` — запуск программы и ожидание от
  вызывающего, от uid вызывающего: после `auth` команда идёт от root.
- SysInfo в `0x5000`; shared memory для vita/help; слот позиции выхода
  `0x708C/0x7090` и код возврата `0x7098`.
- Программа пишет `EXIT_ROW/EXIT_COL` — шелл продолжает с этой позиции.

## Сборка и тесты
- Тулчейн `nightly-2022-11-01`, `build-std`, NASM (boot.asm), GCC (C-программы), GRUB → ISO + 8-МиБ диск.
- Запуск: `qemu-system-x86_64 -cdrom target/os.iso -drive file=target/os.img,format=raw,if=ide`.
- Автотесты (QEMU + QMP): команды, VFS, редиректы, multitask, parallel, persist,
  crash, init, exec, vita, web, fetch и `test_users` — вход, права, sudo,
  adduser/removeuser, блокировка после трёх неудачных попыток.
- Образ с готовыми пользователями: `python3 tools/mkfs.py out.img
  target/programs.list --user tim:secret`.
